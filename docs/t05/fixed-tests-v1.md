# T05 고정 검사 v1 — 지구 밖의 지금

요약: 개선 기능은 공개 보존 관측 기록을 하나의 CSV로 내려받는 기능이다. 아래 기능 검사 10개를 AI A의 구현 시작 전에 고정한다. 이 문서 작성과 기존 사이트 확인은 사전 준비이며, AI A 구현 시작이나 검사 실행 결과가 아니다.

## 확인한 기존 상태

- 사이트: https://suminkim8203.github.io/orbit-iss-board/#records
- 사이트의 ‘이 배포의 소스’ 링크: https://github.com/suminkim8203/orbit-iss-board/tree/a5c034dea460468029e4618f45a47ac5a75bda2b
- 확인 기준일: 2026-09-09 KST
- 현재 관측값, 공개 일별 기록, 브라우저의 일별 캐시, 합성 시험은 구분되어 있다.
- 개별 관측의 원자료 내려받기는 이미 있다. 이번 개선은 공개 보존 관측 기록 전체를 표 형태의 CSV 한 파일로 내려받는 기능이다.
- 실제 AI A 시작 버전은 아래 사전 준비 자료와 검사 실행 기반을 저장한 뒤 별도로 기록한다. 위 배포 버전을 자동으로 A 시작 버전으로 간주하지 않는다.

## 고정 기능 계약

- ‘하루, 하나의 기록’ 영역에 ‘관측 기록 CSV 다운로드’ 버튼을 추가한다.
- 내보내기 대상은 공개 보존 일별 기록이다. 현재 관측값, 브라우저 전용 캐시, 합성 시험, ‘수집 대기’ 표시 행은 제외한다.
- 파일명은 `orbit-iss-records.csv`로 고정한다.
- 날짜 오름차순으로 내보내며, 헤더 뒤에 기록당 데이터 행 하나를 작성한다.
- 헤더와 열 순서는 `관측날짜,고도(km),출처기준시각,조회시각,출처URL`이다.
- 인코딩은 UTF-8 BOM 포함, 줄바꿈은 CRLF, 마지막 행 뒤에도 CRLF를 붙인다.
- 날짜는 저장된 KST 관측 날짜를 사용한다. 출처 기준 시각과 조회 시각은 각각 `YYYY-MM-DDTHH:mm:ss+09:00` 형식으로 표시한다.
- 고도는 화면용 두 자리 반올림값이 아니라 저장된 숫자의 정밀도를 보존한다. CSV의 고도 셀에는 단위 문자를 넣지 않는다.
- CSV 필드에 쉼표·큰따옴표·줄바꿈이 있으면 표준 CSV 이스케이프를 적용한다. 고정 fixture에는 이 문자가 없어 임의 열 인용 없이 작성한다.
- 기록이 0개면 버튼은 비활성화하고 `내려받을 관측 기록이 없습니다.`를 표시한다.
- 내보내기는 조회·수집·수정·삭제를 수행하지 않고 이미 로드된 공개 보존 기록을 사용한다.

## 고정 입력 자료

다음은 검사 전용 합성 자료이며 실제 ISS 관측 증거가 아니다. 실제 공개 기록 파일에 넣지 않는다. 검사 실행 시 별도 fixture로 주입한다. 아래 항목명은 검사 계약의 논리 필드이며 실제 저장소 스키마에 맞춘 어댑터는 준비 단계에서 작성한다. 어댑터는 날짜·값·시각의 의미나 기대값을 바꾸면 안 된다.

| 기록 | 관측날짜(KST) | 저장 고도(km) | 출처 기준 시각(UTC 입력) | 조회 시각(UTC 입력) |
|---|---|---|---|---|
| R1 | 2026-09-08 | 420.123456789 | 2026-09-07T14:59:55Z | 2026-09-07T15:00:05Z |
| R2 | 2026-09-09 | 421.987654321 | 2026-09-09T00:25:35Z | 2026-09-09T00:25:36Z |

두 기록의 출처URL은 모두 `https://api.wheretheiss.at/v1/satellites/25544`이다.

기본 입력은 `[R1, R2]`이다. 각 검사는 독립적으로 초기화한다. F08의 추가 자료는 현재 관측값(고도 430), 브라우저 전용 캐시(2026-09-10, 고도 432), 합성 시험(값 999 pt)으로 정한다. 모두 내보내기 대상에서 제외한다.

기본 입력의 예상 CSV 본문은 다음과 같다. 실제 파일에는 UTF-8 BOM을 앞에 붙이고 모든 줄을 CRLF로 끝낸다.

```csv
관측날짜,고도(km),출처기준시각,조회시각,출처URL
2026-09-08,420.123456789,2026-09-07T23:59:55+09:00,2026-09-08T00:00:05+09:00,https://api.wheretheiss.at/v1/satellites/25544
2026-09-09,421.987654321,2026-09-09T09:25:35+09:00,2026-09-09T09:25:36+09:00,https://api.wheretheiss.at/v1/satellites/25544
```

## 고정 검사 — 정확히 10개

| ID | 입력·행동 | 관찰 가능한 기대값 |
|---|---|---|
| T05-F01 | 공개 기록 `[R1, R2]`를 로드하고 ‘관측 기록 CSV 다운로드’를 한 번 누른다. | 파일 하나가 다운로드되고 파일명은 `orbit-iss-records.csv`이다. |
| T05-F02 | 기본 입력으로 내려받은 파일을 UTF-8로 읽고 헤더를 확인한다. | 앞 3바이트가 UTF-8 BOM이고, 헤더는 지정된 한글 5개 열과 순서에 정확히 일치한다. 줄바꿈은 CRLF이다. |
| T05-F03 | 기본 입력으로 다운로드한 CSV를 파싱한다. | 헤더를 제외한 데이터 행이 정확히 2개이고, 각 행은 5개 열이다. 날짜는 2026-09-08과 2026-09-09이며 ‘수집 대기’ 행은 없다. |
| T05-F04 | 공개 기록을 역순 `[R2, R1]`으로 제공한 뒤 다운로드한다. | CSV 데이터 행은 R1, R2 순서다. 파일 내용은 기본 입력의 예상 CSV와 같다. |
| T05-F05 | 기본 입력을 다운로드하고 고도 열을 확인한다. | 고도는 각각 `420.123456789`, `421.987654321`이다. `420.12`, `421.99`로 줄어들거나 셀에 `km`가 붙지 않는다. |
| T05-F06 | 기본 입력을 다운로드하고 날짜·시각·출처 열을 확인한다. | R1의 관측날짜는 `2026-09-08`, 출처 시각은 `2026-09-07T23:59:55+09:00`, 조회 시각은 `2026-09-08T00:00:05+09:00`이다. R2는 예상 CSV와 일치한다. 두 출처URL도 정확히 일치한다. |
| T05-F07 | 공개 기록을 빈 배열 `[]`로 로드하고 다운로드 영역을 확인한다. | 버튼이 비활성화되고 `내려받을 관측 기록이 없습니다.`가 표시된다. 버튼 조작으로 파일이 생성되지 않는다. |
| T05-F08 | `[R1, R2]`에 더해 위에서 정한 현재 관측값·브라우저 전용 캐시·합성 시험 상태를 준비하고 다운로드한다. | 파일 내용은 기본 입력의 예상 CSV와 같다. 추가 세 자료가 행 또는 값으로 섞이지 않는다. |
| T05-F09 | `[R1, R2]` 로드 후 한 번 다운로드한다. 이어서 ‘새 데이터 조회’ 요청만 통신 실패로 재현하고 다시 다운로드한다. | 조회 실패 이후에도 공개 기록 2개가 유지되며 두 CSV 파일의 바이트 내용이 동일하다. |
| T05-F10 | `[R1, R2]`에서 다운로드 버튼을 두 번 누르고 기록 상태를 다시 확인한다. | 각 클릭이 다운로드 1건씩을 만들고 두 파일 내용이 동일하다. 공개 기록의 날짜·고도·시각·출처·순서가 실행 전후 같고 기록 수는 2개다. |

## 실행과 증거 보존 규칙

- 실제 API의 현재 값이나 다음 날짜의 수집을 기다리지 않고 고정 fixture로 10개를 재현한다.
- 파일 검사와 UI 검사를 한 명령으로 실행할 수 있는 검사 기반을 준비하여, A 시작 전에 실행 명령·검사 파일·fixture와 이 문서를 같은 저장소에 보존한다.
- 각 실행은 10개 모두를 실행하고 ID별 PASS/FAIL과 실행 시각을 저장한다. 실행 불가 항목을 PASS로 처리하지 않는다.
- 위 표는 기대값 계약이다. 이번 준비 단계에서 10개를 실행하거나 통과했다고 주장하지 않는다.
- 고정 검사의 삭제·완화·기대값 변경은 0건이어야 한다.
- 기존 과제 4 검사는 유지하며 별도로 실행할 수 있다. 기존 검사 수를 이 고정 검사 10개의 통과 수에 합산하지 않는다.
- 실제 파일 다운로드 이름에 운영체제·브라우저가 붙이는 중복 번호는 F10의 파일명 판정에 사용하지 않는다. 내용의 동일성을 비교한다.
- 실패 요청은 브라우저 전체를 오프라인으로 바꾸는 대신 새 데이터 조회 요청의 실패로 재현한다. 이미 로드한 사이트와 내보내기 기능을 계속 검사할 수 있어야 한다.

## AI A 시작 전에 따로 정할 운영값

- AI A와 AI B의 서비스·정확한 모델: 미정. B는 A와 다른 서비스 또는 모델인 무료 AI를 사용한다.
- 공통 시간 상한: 미정. 제안은 각 45분이다.
- 공통 요청 수 상한: 미정. 제안은 각 8회이며 최초·수정·인수인계 요청을 포함한 사용자 메시지 수로 센다.
- 공통 최초 요청과 측정 범위: 미정. 저장소 문서로 고정한다.
- A 시작 소스 버전과 시작 시각: 아직 없음. 사전 준비를 저장한 뒤 실제 구현 시작 때 기록한다.

권장 역할 분담은 A가 기본 다운로드와 열 구성을 구현한 후 인계하고, B가 남은 경계 상황을 해결하여 같은 10개를 마치는 것이다. 실제 통과 수와 남은 실패는 실행 결과 그대로 기록하며 미리 정하거나 꾸미지 않는다.
