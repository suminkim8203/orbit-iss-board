# T05 공개 비교 보고서

## 요약

도구 Y(B)는 빈 공개 기록 상태에서 관제 화면 전체가 중단되던 문제를 고쳤고, 최종 고정 검사 10개를 모두 통과했다. 서비스·모델 이름은 이 공개용 보고서에 싣지 않았다.

| 구분 | 도구 X(A) | 도구 Y(B) |
| --- | ---: | ---: |
| 최종 고정 검사 통과 | 9 / 10 | 10 / 10 |
| 남은 고정 검사 실패 | T05-F07 | 없음 |
| 오류 회차 | 2 | 2 |
| 사용자 작업 메시지 | 1 / 8 | 2 / 8 |
| 측정 시간 | 313.05초 / 2,700초 | 541.116초 / 2,700초 |

최종 제품 소스 주소는 Git 개정 `cfbc80fdcdec373baf2f0b7e78c81d0df94e7f80`이다. 이 개정에는 B 시작 기록과 빈 상태 처리 코드가 포함되어 있으며, 저장소 내부의 외부 공개 주소는 제공되지 않았으므로 배포나 공개 게시를 수행하지 않았다.

## 확인 방법

1. `HANDOFF.md`의 SHA-256을 `A-END.json`의 값과 대조해 인계 문서가 바뀌지 않았음을 확인한다.
2. `node scripts/t05-verify-frozen.mjs`로 고정 문서·fixture·검사 9개 파일과 10개 ID를 확인한다.
3. `evidence/t05/B-2026-09-10T01-10-19-364Z.json`에서 T05-F01~F10의 최종 PASS를 확인한다.
4. `npm test --prefix app`, `npm run build --prefix app`, `npm run lint --prefix app`, 자산·비밀값 검사 결과를 재실행해 확인한다.

## B의 판단

1. 빈 상태에서는 실제 관측값으로 보일 수 있는 좌표·고도·시각·원자료를 만들지 않고, 각각 명확한 대기 안내를 보인다.
2. 기존 공개 기록과 새 데이터 조회 흐름은 그대로 두어, 기록이 생기면 기존 화면과 CSV 동작으로 복귀한다.
3. 이 보고서는 검증 결과를 설명할 뿐이며, 사용자나 제3자의 품질 판단을 대신하지 않는다.
